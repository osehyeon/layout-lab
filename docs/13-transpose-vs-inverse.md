# 13. `Aᵀ` 와 `A⁻¹` — 다른 연산이다

[12-f2-primer.md](12-f2-primer.md) 를 읽고 나면 layout 을 행렬로 보게 되는데, 거기서 **전치와 역행렬을 섞기 쉽다.** 특히 지금까지 본 예에서 둘이 **우연히 같게 나오기 때문**이다. 왜 그런지, 언제 깨지는지를 정리한다.

표기는 12 문서를 따른다 — 스칼라는 *소문자 이탤릭*, 벡터는 **소문자 볼드**, 행렬은 **대문자 볼드**.

> **한 줄로.** LinearLayout 이 쓰는 것은 **`A⁻¹`** 이고 전치와는 무관하다. 순열 배치에서만 `Aᵀ = A⁻¹` 이 성립한다.

---

## 1. 무엇을 하는 연산인가

**전치 `Aᵀ`** — 행과 열을 맞바꾼다. `Aᵀ[i][j] = A[j][i]`.

- **언제나 존재한다.** 조건이 없다
- 계산이 자명하다 — 읽는 방향만 바꾸면 된다
- 정사각이 아니어도 된다

**역행렬 `A⁻¹`** — `A A⁻¹ = I` 를 만족하는 행렬.

- **없을 수도 있다.** 정사각이고 full rank 여야 한다
- 계산에 **가우스 소거법**이 필요하다
- 12 문서 §2 의 **곱셈 역원**을 행렬로 옮긴 것이다. *x* × *x*⁻¹ = 1 이 **A** **A**⁻¹ = **I** 가 된다

| | `Aᵀ` | `A⁻¹` |
|---|---|---|
| 존재 | **항상** | 가역일 때만 |
| 계산 | 읽는 방향 바꾸기 | 가우스 소거법 |
| 뜻 | 행·열 역할 교환 | **되돌리기** |

---

## 2. layout 에서 각각 무슨 뜻인가

layout **A** 는 **하드웨어 좌표 → 텐서 인덱스** 사상이다(12 문서 §7). 그러면:

| | 뜻 |
|---|---|
| **A** | lane·register 좌표를 넣으면 **원소 번호**가 나온다 |
| **A⁻¹** | 원소 번호를 넣으면 **누가 들고 있는지**가 나온다 — 방향을 뒤집은 것 |
| **Aᵀ** | 입력 비트와 출력 비트의 **역할을 맞바꾼 것** — layout 으로서는 의미가 없다 |

`A⁻¹` 은 쓸모가 분명하다. "원소 5 는 어느 lane 에 있나"를 묻는 것이고, 그래서 변환 `B⁻¹ ∘ A` 가 "A 배치에서 꺼내 B 배치로 넣는" 대응표가 된다.

> **`A` 와 `B` 는 무엇이고, 왜 이 순서인가.** 둘 다 **하드웨어 좌표 → 텐서 인덱스** 로 방향이 같다. `A` 는 값이 **지금 놓여 있는** 배치(생산자가 남긴 것), `B` 는 소비자가 **요구하는** 배치다. 변환은 **출발 좌표 → 도착 좌표**여야 하므로, `A` 로 인덱스를 풀고 `B⁻¹` 로 그 인덱스가 도착지의 어느 좌표인지 되묻는다 — 그래서 `B⁻¹ ∘ A` 다. (`B ∘ A⁻¹` 이면 인덱스 → 인덱스가 되어 말이 안 된다.) Triton 의 `include/triton/Tools/LinearLayout.h` 가 이 순서를 그대로 못박는다:
>
> ```
> // Formally, if C = A.invertAndCompose(B), then for all x, C(x) = y implies
> // A(x) = B(y), or in other words A(x) = B(C(x)).  If B is invertible, then
> // C(x) = B^-1(A(x)), which is how this function gets its name.
> //
> //   - R is an LL representing registers, mapping (lane, warp) to a 2D index.
> //   - S is an LL representing shared memory, mapping offset to a 2D index.
> //     R.invertAndCompose(S) computes this transformation.
> ```
>
> 여기서 `A` = `R`(레지스터, 출발), `B` = `S`(SMEM, 도착)다.

### `C = B⁻¹A` 와 `A x = y` 는 무슨 관계인가

**`C` 는 새로운 종류의 물건이 아니다.** `A x = y` 를 **두 번 이어 붙여 하나로 접은 것**이다.

![A x = y 와 C = B⁻¹A 의 관계](figures/compose-vs-apply.svg)

`A x = y` 는 *좌표를 넣으면 원소 번호가 나온다*. `B` 도 같은 물건이므로 `B⁻¹` 은 *원소 번호를 넣으면 좌표가 나온다*. "이 값은 어디로 가야 하나"는 둘을 잇는 것이다.

```
도착 좌표 = B⁻¹( A x ) = (B⁻¹ A) x = C x
```

결합법칙으로 **둘을 미리 곱해 `C` 하나로 만들어 두면** 코드 생성 때는 `C x` 한 번이다.

| | 입력 | 출력 |
|---|---|---|
| `A x` | 하드웨어 좌표 | **원소 번호** |
| `B⁻¹ y` | 원소 번호 | **하드웨어 좌표** |
| **`C x`** | 하드웨어 좌표 | **하드웨어 좌표** |

`C` 만 입력과 출력이 **같은 공간**이다. 그래서 `C` 에만 "**항등인가?**" 라는 질문이 성립한다 — `A` 에 대고 그것을 묻는 것은 lane 번호와 원소 번호를 비교하는 꼴이라 뜻이 없다.

그리고 `C` 도 **기저 목록**이다. 위 그림에서 `C = [4, 1, 2]` 이고, "lane 3 은 어디로?"를 푸는 것은 [12-f2-primer.md](12-f2-primer.md) §11 의 *기저 → 표* 계산 — **켜진 비트의 기저를 XOR** — 을 `C` 에 대고 하는 것뿐이다. 새 연산은 하나도 없다.

```
1. A, B 기저를 얻는다      PTX 규정 읽기        사람, 명령당 1회
2. C = B⁻¹A               행렬 × 행렬          컴파일 타임 1회  ← 여기만 새로 붙는 단계
3. C 를 본다               [1,2,4] 면 I        명령 0개
4. C x                    행렬 × 벡터          12 문서 §11 그대로, 필요한 lane 만
```

`C` 자리에 무엇이 오든 3·4 단계는 같다. 이것이 "배치 쌍마다 있던 lowering 이 하나로 줄었다"의 실체다.

---

`Aᵀ` 에는 그런 해석이 없다. 입력 공간과 출력 공간은 애초에 다른 것(하드웨어 좌표 vs 텐서 인덱스)이라, 둘의 역할을 바꾼다는 것이 물리적으로 무엇을 뜻하지 않는다.

> **"transpose" 라는 단어가 두 층에서 다르게 쓰인다.** `tl.trans` 는 **텐서 축의 순열**이고 기저에 작용한다(11 문서 §1). 행렬 전치 `Aᵀ` 는 **행렬 자체의 연산**이고 layout 연산이 아니다. 이름이 같아서 겹쳐 읽히기 쉽다.

---

## 3. 그런데 왜 같아 보였나 — 순열이라서

![Aᵀ 와 A⁻¹ 의 비교](figures/transpose-vs-inverse.svg)

**순열 행렬은 직교행렬이라 `Pᵀ = P⁻¹` 이 항상 성립한다.** 어느 체 위에서든 그렇다.

그리고 지금까지 본 예가 **전부 순열**이었다 — `[1, 2, 4, 8, 16]`, `[4, 8, 16, 1, 2]` 는 모두 **열마다 1 이 하나**인 행렬이다(기저값이 전부 2의 거듭제곱이니까). 그래서 둘이 같게 나왔다.

```
순열   [4, 8, 16, 1, 2]     A⁻¹ = [8, 16, 1, 2, 4]     Aᵀ = [8, 16, 1, 2, 4]    같다
항등   [1, 2, 4, 8, 16]     A⁻¹ = 자기 자신              Aᵀ = 자기 자신           같다
스위즐 [1, 2, 5, 10]        A⁻¹ = [1, 2, 5, 10]         Aᵀ = [5, 10, 4, 8]      다르다
```

**스위즐에서 깨진다.** `5 = 0101`, `10 = 1010` 처럼 **한 열에 1 이 여럿**이면 직교가 아니고, 전치와 역행렬이 갈라진다.

> **곁가지 — 스위즐은 자기 자신이 역원이다.** 위 표에서 `A⁻¹ = A` 인 데 주목할 것. XOR 로 뒤집는 연산이라 **두 번 하면 제자리**로 돌아온다(involution). 그래서 SMEM 에 넣을 때와 꺼낼 때 **같은 식**을 쓴다 — 10 문서 §3 이 "저장부와 로드부의 스위즐 식이 일치해야 한다"고 한 것이 이 성질 덕분이다.

---

## 4. `A⁻¹` 이 없을 때

브로드캐스트가 그 경우다. 여러 lane 이 같은 원소를 들면 **비단사**이고, 되돌릴 수 없다 — "원소 5 는 누가 들고 있나"에 답이 여럿이기 때문이다. 기저값에 **0** 이 있으면 그 비트는 아무 데도 기여하지 않고, 행렬에 **0 인 열**이 생겨 rank 가 떨어진다.

이때 Triton 이 쓰는 것이 `invertAndCompose` 다. 역행렬을 따로 만들지 않고 **합성과 묶어서**, 모호한 자리를 결과에 유리하게 고른다. 기준은 **최소 노름 해 = 최소 데이터 이동**이라고 코드에 박혀 있다([11-linearlayout-history.md](11-linearlayout-history.md) §3).

## 5. F₂ 에서의 계산

가우스 소거법이 그대로 돌아가는데, 12 문서 §8 의 성질 덕에 훨씬 단순하다.

| 실수에서 | F₂ 에서 |
|---|---|
| 피벗으로 나눈다 | 0 아닌 값이 1 뿐이라 **나눗셈이 없다** |
| 행의 *c* 배를 뺀다 | −**x** = **x** 라 **그냥 XOR** |
| 수치 오차 | **없다** — 정확하다 |

```python
def inverse(bases, n):
    a = list(bases)                    # 원본
    b = [1 << j for j in range(n)]     # 단위행렬
    for col in range(n):
        piv = next((k for k in range(col, n) if a[k] >> col & 1), None)
        if piv is None:
            return None                # 가역이 아니다
        a[col], a[piv] = a[piv], a[col]
        b[col], b[piv] = b[piv], b[col]
        for k in range(n):
            if k != col and (a[k] >> col & 1):
                a[k] ^= a[col]         # 빼기가 아니라 XOR
                b[k] ^= b[col]
    return b
```

행 하나가 정수 하나라 **행 연산 한 번이 정수 XOR 한 번**이다. `n × n` 행렬을 정수 `n` 개로 담을 수 있다.

## 6. 정리

| 묻는 것 | 쓰는 것 |
|---|---|
| 두 배치가 같은가 | **기저 목록 직접 비교** — 행렬 계산도 필요 없다 |
| 다르면 무엇이 어긋났나 | **`B⁻¹ ∘ A`** |
| 이 원소를 누가 들고 있나 | **`A⁻¹`** |
| `Aᵀ` | **쓰지 않는다** |

`B⁻¹ ∘ A = I` 는 "같은지 검사하는 조건"이 아니라 **변환을 계산했더니 나온 결과**다. 순서가 이렇다 — 변환을 구한다 → 항등이 나왔다 → 옮길 것이 없다.

## 7. 직접 해 보기

[`examples/f2_playground.py`](examples/f2_playground.py) 에 역행렬·합성·비가역 확인이 들어 있다. 전치를 추가로 보려면:

```python
def transpose(bases, n):
    return [sum(((bases[i] >> j) & 1) << i for i in range(n)) for j in range(n)]

for name, B, n in [('순열', [4, 8, 16, 1, 2], 5), ('스위즐', [1, 2, 5, 10], 4)]:
    print(name, 'A^-1 =', inverse(B, n), ' A^T =', transpose(B, n))
```
