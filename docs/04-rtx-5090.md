# 04. NVIDIA GeForce RTX 5090 (데스크톱, GB202)

> 작성일 2026-09-11. 1차 자료 사본은 `docs/sources/rtx-5090/`에 있음 (목록: [SOURCES.md](sources/rtx-5090/SOURCES.md)).
> 표기: 처리량은 NVIDIA 공식 수치를 **환산 없이** 적고 값마다 **[sparse]**(2:4 structured sparsity 적용, dense의 2배) 또는 **[dense]** 를 붙임. 데이터시트·제품 페이지 공식 표기가 있으면 그 값, 없으면 백서 표의 dense 값. "(미확인)"은 1차 자료로 확인하지 못한 값이고, "(계산)"은 공식 수치에서 산술로 도출한 값임.
> Blackwell 공통 아키텍처와 sm_100 vs sm_120의 상세 비교는 [01-architecture.md](01-architecture.md)를 참조.

### 2.2 정밀도별 연산 성능 (백서 Appendix A Table 3, boost clock 기준)

값마다 [sparse]/[dense]를 붙였다.
- FP4는 제품 페이지 헤드라인("AI TOPS")이 sparse라서 그 값을 적었다.
- 나머지 Tensor 행은 백서 표의 dense 값이다.
- non-Tensor 행(FP32, INT32, FP64 등)은 sparsity가 없으므로 모두 [dense]다.

백서 각주 1은 "Peak rates are based on GPU Boost Clock", 각주 2는 "Effective TOPS / TFLOPS using the Sparsity Feature"이다.

| 정밀도 | RTX 5090 | RTX 4090 | 5090/4090 |
|---|---|---|---|
| **FP4 Tensor** (FP32 accumulate) | **3,352 [sparse]** (제품 페이지 "3,352 AI TOPS") | N/A | 신규 |
| **FP8 Tensor**, FP16 accumulate | **838 [dense]** | 660.6 [dense] | 1.27× |
| **FP8 Tensor**, FP32 accumulate | **419 [dense]** | 330.3 [dense] | 1.27× |
| **FP16 Tensor**, FP16 accumulate | **419 [dense]** | 330.3 [dense] | 1.27× |
| **FP16 Tensor**, FP32 accumulate | **209.5 [dense]** | 165.2 [dense] | 1.27× |
| **BF16 Tensor**, FP32 accumulate | **209.5 [dense]** | 165.2 [dense] | 1.27× |
| **TF32 Tensor** | **104.8 [dense]** | 82.6 [dense] | 1.27× |
| **INT8 Tensor** | **838 TOPS [dense]** | 660.6 [dense] | 1.27× |
| FP6 Tensor | 백서에 "FP6 지원"만 있고 수치는 표에 없음 (미확인) | – | – |
| **FP32** (non-Tensor, shader) | **104.8** TFLOPS | 82.6 | 1.27× |
| FP16 / BF16 (non-Tensor) | 104.8 / 104.8 (FP32와 1:1) | 82.6 | – |
| INT32 (non-Tensor) | 104.8 TOPS (INT32와 FP32 코어 통합) | 41.3 | 2.5× |
| **FP64** (non-Tensor) | 백서 표에 없음. CUDA Programming Guide CC 12.0 절에 따르면 SM당 FP32 core 128개, **FP64 core 2개**이므로 **FP32의 1/64**이고 약 **1.64 TFLOPS** (계산) | – | – |
| RT TFLOPS | 317.5 (제품 페이지 표기 318) | 191 | – |

핵심 해석:
- **GeForce는 FP32 accumulate가 반속이다.** FP16/BF16 Tensor는 FP32 accumulate(209.5)가 FP16 accumulate(419)의 절반이고, FP8도 FP32 acc(419)가 FP16 acc(838)의 절반이다. 학습과 대부분의 추론 커널은 FP32 accumulate를 쓰므로 **실효 BF16 dense는 209.5 TFLOPS**로 보는 것이 맞다. CUTLASS 문서의 SM120 표도 FP8 계열 `mma.sync`를 "1x Ada FP8 Tensor Core (2x for FP32 accumulator)"로, FP4 block-scaled를 "2x Ada FP8 Tensor Core (4x for FP32 accumulator)"로 적어 이 비율과 맞는다 (https://github.com/NVIDIA/cutlass/blob/main/media/docs/cpp/blackwell_functionality.md).
- 백서는 FP4 수치를 "with FP32 Accumulate"로 명기한다. 즉 FP4 1,676 TFLOPS [dense](백서 값, 헤드라인 3,352 [sparse]의 절반)는 FP8(FP32 acc) 대비 4배이고 FP16 acc 기준 FP8 대비 2배이다 (백서 Figure 8 "FP4, double throughput of FP8").
- 기존 정밀도(FP16/FP8/INT8/TF32/FP32)의 세대 간 향상은 모두 **약 1.27배**이다. SM 수 170/128 = 1.33에 클럭 2407/2520을 곱한 값과 같다. 아키텍처상 큰 변화는 **FP4/FP6 지원과 메모리 대역폭(1.78배)**이다. Puget Systems도 FP/BF16 +27%를 "somewhat disappointing"이라 평하고, 대역폭 향상을 AI 워크로드의 핵심 이점으로 꼽았다 (https://www.pugetsystems.com/labs/articles/nvidia-geforce-rtx-5090-amp-5080-ai-review/).

## 3. 지원 기능

### 3.1 Compute capability와 명령어셋 (sm_120)

- **Compute capability 12.0 (sm_120)**. 제품 페이지 "CUDA Capability 12.0"과 NVIDIA CUDA GPU 표로 확인했다 (https://developer.nvidia.com/cuda-gpus). B200은 10.0(sm_100)이다.
- **tcgen05 / TMEM(Tensor Memory) 없음.** SM12x는 tcgen05와 TMEM을 쓰지 않고, SM8x처럼 warp-level `mma.sync`를 쓴다 (Colfax Research, https://research.colfax-intl.com/cutlass-tutorial-nvfp4-blockscaled-gemm-on-nvidia-rtx-pro-blackwell-gpus-sm12x/). 대신 `mma.sync`에 FP4/FP6/FP8과 **하드웨어 block scaling**이 추가됐다: `kind::f8f6f4`, `kind::mxf8f6f4.block_scale`, `kind::mxf4.block_scale`, `kind::mxf4nvf4.block_scale.scale_vec::[2X|4X]` (CUTLASS 문서).
- SM12x에서 사용 가능한 기능은 TMA, Cluster Launch Control(CLC), Programmatic Dependent Launch(PDL)이다. Warpgroup register re-allocation은 sm_120a/sm_120f 타깃에서만 된다 (Colfax).
- **Cluster multicast 없음.** CUTLASS 문서에 "On Geforce series graphics card, there is no multicast feature therefore the cluster shape is fixed to 1x1x1"로 적혀 있다.
- sm_100과의 차이(2-SM UMMA, TMEM, 227 KB SMEM 등)는 [01-architecture.md](01-architecture.md) 참조.

### 3.3 AI, 그래픽, 미디어 기능

- **NVFP4 / MXFP4 / FP6 / FP8**: 5세대 Tensor Core가 FP4와 FP6을 새로 지원하고, 2세대 FP8 Transformer Engine을 탑재했다 (백서 p.15). TensorRT 10.8에서 FP4를 지원한다 (NVIDIA 블로그 2025-01-30, https://developer.nvidia.com/blog/new-ai-sdks-and-tools-released-for-nvidia-blackwell-geforce-rtx-50-series-gpus/).
- **DLSS 4 Multi Frame Generation**: 렌더링된 프레임 1장당 최대 3장의 추가 프레임을 생성한다. 새 frame generation 모델은 이전 방식보다 40% 빠르고 VRAM을 30% 덜 쓰며, optical flow를 하드웨어 대신 AI 모델로 계산한다. 프레임 페이싱은 display engine의 Flip Metering이 맡는다 (백서 p.35–36). 2026-09 수집 시점의 제품 페이지에는 DLSS 5(3D-Guided Neural Rendering)와 "Dynamic Multi Frame Generation (6X Mode)"도 표기되어 있다.
- **Neural Shaders**: 셰이더 안에서 작은 신경망을 실행하는 방식이다. RTX Neural Materials, Neural Texture Compression, Neural Radiance Cache, Neural Faces 등이 있으며, Blackwell SM은 "neural shaders에 최적화"되어 있다 (백서 p.39–45). 이를 위해 INT32 코어가 FP32 코어와 통합됐고, point-sampled texture 처리량이 2배가 됐다.
- **AI Management Processor (AMP)**: RISC-V 기반 GPU context scheduler로, AI와 그래픽 워크로드의 스케줄링을 CPU 대신 맡는다 (백서 p.25).
- **NVENC 9세대 ×3, NVDEC 6세대 ×2**: AV1/HEVC 품질이 5% BD-BR 개선됐고, **4:2:2 H.264/HEVC 인코드와 디코드**, AV1 UHQ 모드를 지원한다. NVDEC은 H.264 디코드가 2배 빨라졌다 (백서 p.28–30).

## 4. 비교

### 4.1 RTX 5090 vs RTX PRO 6000 Blackwell (같은 GB202)

| 메모리 | 32 GB GDDR7 | 96 GB | MIG 가이드 표 |

→ 커널 수준(ISA, block-scaled MMA, SMEM 한도)에서는 **사실상 같은 개발 타깃**이다. 차이는 용량(32 GB vs 96 GB), SM 수, 멀티 GPU와 가상화 기능(P2P, MIG), 전력 및 폼팩터 쪽에 있다. PRO 6000의 정밀도별 TFLOPS, TGP, ECC 등 상세는 같은 docs/ 안의 RTX PRO 6000 문서를 참조한다 (본 문서에서는 교차 검증하지 않음).

### 4.2 RTX 5090 vs RTX 4090 (세대 간, 백서 Table 3)

| 항목 | RTX 4090 (AD102) | RTX 5090 (GB202) | 비율 |

| Boost clock | 2,520 MHz | 2,407 MHz | 0.96× |
| 메모리 | 24 GB GDDR6X, 384-bit, 21 Gbps | 32 GB GDDR7, 512-bit, 28 Gbps | 1.33× (용량) |
| 대역폭 | 1,008 GB/s | 1,792 GB/s | **1.78×** |
| L2 | 72 MB | 96 MB | 1.33× |

| FP8 Tensor (FP16 acc, dense) | 660.6 | 838 | 1.27× |
| 최저 정밀도 dense peak | FP8 660.6 | FP4 1,676 | 2.54× (정밀도가 달라 직접 비교는 주의) |
| TGP | 450 W | 575 W | 1.28× |
| PCIe | Gen 4 | Gen 5 | – |

→ 연산량과 전력 증가는 거의 비례한다(≈1.27–1.28배). **token generation처럼 대역폭에 묶인 LLM decode**는 대역폭 증가 덕을 크게 본다. Puget은 llama.cpp token generation에서 4090 대비 약 +29%를 측정했다 (5.1 참조).

### 4.3 알려진 초기 도입(early-adopter) 이슈 (출처 있는 것만)

1. **PyTorch 호환성**: 출시(2025-01) 당시 stable PyTorch에는 sm_120 커널이 없었다. "sm_120 is not compatible with the current PyTorch installation" 오류가 보고됐다 (https://forums.developer.nvidia.com/t/rtx-5090-not-working-with-pytorch-and-stable-diffusion-sm-120-unsupported/338015, 링크만). PyTorch 2.7(2025-04)의 cu128 wheel로 해결됐다.
2. **Linux 드라이버**: proprietary 커널 모듈은 미지원이라 `nvidia-open`을 써야 한다. 출시 시점에는 Linux 정식 드라이버가 늦게 나와, Phoronix는 CUDA 12.8 번들 드라이버로 테스트했다.
3. **llama.cpp prompt processing 이상치 (Windows, 출시 시점)**: Puget은 5090의 prompt processing 점수가 4080 SUPER 수준으로 낮게 나왔다고 보고했다. Linux에서는 재현되지 않아 드라이버 문제로 추정했다.
4. **12V-2x6 (16-pin) 커넥터 과열**: der8auer가 자신의 RTX 5090 FE를 FurMark(약 570 W)로 측정한 결과, 12V 와이어 6가닥 중 하나에 **22 A 이상**, **150 °C 이상**이 측정됐다. 전류 불균형이 원인으로 추정된다 (Tom's Hardware 2025-02-11, https://www.tomshardware.com/pc-components/gpus/rtx-5090-cable-overheats-to-150-degrees-celsius-uneven-current-distribution-likely-the-culprit). 장시간 AI 부하에서는 power limit 설정과 케이블 점검을 권장한다.
5. **멀티 GPU**: P2P가 없어 vLLM/TensorRT-LLM tensor parallel 구동 시 NCCL 문제가 보고됐다 (NVIDIA 포럼 2025-03, 이후 신버전 NCCL로 해결됐다고 보고).
6. **sm_120 커널 생태계 미성숙 (2025–2026)**: NVFP4 MoE grouped GEMM 오출력 (https://github.com/NVIDIA/cutlass/issues/3096), B200 크기 tile config의 SMEM overflow (https://github.com/NVIDIA/TensorRT-LLM/issues/11368, GB10 사례) 등이 있다 (모두 링크만). Tom's Hardware(2026)는 llama.cpp에서 262K context 사용 시 5090의 TTFT가 약 30분까지 늘어나는 성능 절벽을 보고했다.

## 5. 성능 참고 (제3자 벤치마크)

모든 수치는 출처의 조건에 종속되며, 조건이 다르면 직접 비교할 수 없다.

### 5.1 LLM 추론

**(a) Puget Systems, RTX 5090 & 5080 AI Review (2025-01, Windows, Ryzen 9 9950X, "balanced" power profile)**
https://www.pugetsystems.com/labs/articles/nvidia-geforce-rtx-5090-amp-5080-ai-review/
- llama.cpp token generation: **RTX 4090 대비 약 +29%** (절대 tok/s 값은 차트 이미지에만 있어 텍스트로 추출하지 못함, 미확인).
- llama.cpp prompt processing: 이상하게 낮게 나옴 (드라이버 문제로 추정, 4.3 참조).
- MLPerf Client (ONNX Runtime/DirectML): TTFT가 100 ms 미만인 유일한 GPU였고, 4090은 약 33% 느림.

**(b) Knoop & Holtmann, arXiv:2601.09527 (2026-01), vLLM 0.12 + CUDA 12.9, AIPerf, DCGM 전력 텔레메트리, 클라우드 인스턴스**
https://arxiv.org/abs/2601.09527

| 워크로드 (Qwen3-8B, NVFP4) | RTX 5090 1× | RTX 5090 2× (TP=2) |
|---|---|---|
| RAG-8k, concurrency 8: throughput / TTFT | **411 TPS / 450 ms** | 530 TPS / 620 ms |
| RAG-16k, concurrency 8 | 232 TPS / 1,216 ms | 303 TPS / 1,478 ms |
| API (짧은 context), c64 | 4,678 TPS / 131 ms | 4,466 TPS / 173 ms |
| API peak | 6,894 TPS | 7,438 TPS |
| 에너지 (RAG-8k) | 239 Wh/MTok | 330 Wh/MTok |

- 양자화 비교 (Qwen3-8B, 8k, 5090 1×, c8): **BF16 260 TPS, W4A16 314 TPS, NVFP4 411 TPS**. NVFP4는 BF16 대비 1.58배 빠르고 에너지는 41% 적게 쓴다 (403 → 239 Wh/MTok). 품질 손실은 MMLU −2.2%, GSM8K −1.9%.
- GPT-OSS-20B (MXFP4), 5090 1×, 8k: 319–424 TPS. 32k에서는 100 TPS이며, 64k context는 2장이 필요.
- Multi-LoRA agentic (Qwen3-8B NVFP4, 2k, adapter 3개): 1×에서 889 TPS(c16) → 1,683 TPS(c64). **2×는 1,492 TPS(c64)로 오히려 느리다.** 저자들은 짧은 context에서는 TP 통신 오버헤드가 이득을 넘는다고 해석했다. P2P가 없는 PCIe 환경이라는 점과도 맞는 결과다.
- Gemma3-12B NVFP4의 TP=2 확장 효율은 1.14배에 그친다.

**(c) Tom's Hardware, Qwen 3.8 27B 벤치마크 (2026, Ryzen 7 9800X3D, 64 GB DDR5, Ubuntu 26.04)**
https://www.tomshardware.com/tech-industry/artificial-intelligence/benchmarking-qwen-3-8-27b-on-rtx-5090-and-beyond-vram-capacity-alone-cant-overcome-severe-software-and-inference-engine-bottlenecks
- vLLM, NVFP4, 5090 1장: 기본 recipe의 context 한도가 32K이고, VRAM 부족으로 MTP(multi-token prediction)를 켤 수 없다. decode는 **약 20 tok/s**.
- vLLM, 5090 2장: decode 70–80 tok/s, MTP를 켜면 **100–110 tok/s** (prefill 비용은 커짐).
- SGLang, 5090 1장: vLLM 1장 recipe보다 **약 3배 빠르고** context는 37,740까지 가능.
- llama.cpp (Unsloth GGUF): 262K context 할당은 되지만 long-context 성능이 무너진다 (TTFT 약 30분). 기사는 버그로 추정.
- 결론: 32 GB에서 dense 27B급 모델은 가능하지만 long-context를 쓰려면 2장이나 더 큰 VRAM이 필요하고, 런타임 선택이 중요하다.

### 5.2 이미지 생성, 기타 AI

- **NVIDIA (벤더 수치)**, TensorRT FP4 FLUX (2025-05-14): RTX 5090에서 FP4는 FLUX transformer의 FC layer 기준 **FP8 대비 최대 3.1배**다. 파이프라인 end-to-end는 FLUX.1-dev 3,852 ms, FLUX.1-schnell 590 ms이고, low-VRAM 모드에서 FP4 메모리 사용량은 11.1 GB (https://developer.nvidia.com/blog/nvidia-tensorrt-unlocks-fp4-image-generation-for-nvidia-blackwell-geforce-rtx-50-series-gpus/).
- 백서 (벤더 수치): FLUX.dev 30 step 기준 4090 FP16은 15초, 5090 FP4는 "just over five seconds".
- Phoronix: CUDA, OptiX, OpenCL, Vulkan compute 전반에서 이전 세대 대비 세대 비교 결과를 제공한다 (수치는 차트에만 있음, 미확인). 570.86.10 드라이버로 "running very well and without issue".

### 5.3 학습

- 신뢰할 만한 **제3자 학습(throughput) 벤치마크 수치는 이번 조사에서 확보하지 못했다 (미확인).**
- NVIDIA/Unsloth 블로그(벤더 주장): Blackwell에서 Unsloth는 학습 속도 2배, VRAM 70% 절감, 단일 GPU에서 최대 40B 파라미터 fine-tuning이 가능하다고 한다. 이 수치는 GeForce RTX 50, RTX PRO 6000, DGX Spark를 합쳐 말한 것이고, 5090 32 GB에 해당하는 조건은 명시되지 않았다 (https://developer.nvidia.com/blog/train-an-llm-on-an-nvidia-blackwell-desktop-with-unsloth-and-scale-it/).
- 이론 상한: BF16 Tensor(FP32 acc) dense 209.5 TFLOPS. 이는 4090의 1.27배이며, FP32 accumulate가 반속인 GeForce 특성이 반영된 값이다.

## 6. 연구 가능 주제

32 GB 단일 카드, PCIe 전용(P2P/NVLink 없음), sm_120, FP4 지원이라는 조건에 맞춘 방향이다. 난이도는 ★(쉬움)~★★★★(어려움).

### 6.1 NVFP4 / MXFP4 / FP8 양자화 추론 (7B–32B)
- **왜 이 GPU인가**: FP4 3,352 AI TOPS [sparse]와 1.79 TB/s 대역폭을 갖췄다. arXiv 2601.09527에서 NVFP4는 BF16 대비 1.58배 빠르고 에너지를 41% 덜 쓰는 것으로 측정됐다. 32 GB라서 8–14B는 BF16 baseline까지 같은 카드에서 비교할 수 있고, 27–32B는 4-bit에서만 올라간다. KV cache 여유를 두고 정확도, 속도, 에너지의 trade-off를 정량화하는 데 적합하다.
- **SW**: vLLM (NVFP4 kernels, CUDA 12.8+), TensorRT-LLM / TensorRT Model Optimizer (NVFP4 PTQ/QAT), llm-compressor, SGLang, lm-eval.
- **주제 예시**: NVFP4 vs MXFP4 vs W4A16 품질 손실의 모델 크기 의존성, FP8 KV cache, long-context에서 KV cache 양자화가 품질에 주는 영향.
- **난이도**: ★★

### 6.2 sm_120 block-scaled MMA 커널 개발 (저비용 개발 플랫폼)
- **왜 이 GPU인가**: $1,999(MSRP)급 카드로 NVFP4/MXFP4 block-scaled Tensor Core 명령(`mma.sync ... block_scale`)을 직접 다룰 수 있다. 같은 sm_120인 RTX PRO 6000 Blackwell과 ISA 수준에서 동일하므로, 여기서 만든 커널은 **RTX PRO 6000, (sm_121) GB10 계열로 이식하기 쉽다** (GB10은 tile/SMEM 조정이 필요할 수 있음, TRT-LLM #11368 참조).
- **B200(sm_100)으로 그대로 이식되지 않는 것**:
  - sm_120 커널은 `mma.sync`(register 기반, 동기)를 쓴다. sm_100에서 peak를 내려면 `tcgen05.mma`, TMEM accumulator, single-thread issue, 2-SM(cta_group::2) 구조로 **재설계**해야 한다. `mma.sync` 코드도 PTX 수준에서는 sm_100에서 돌 수 있으나 peak 대비 성능은 미확인이다.
  - 99 KB(블록당) SMEM을 전제로 한 tile config는 B200의 227 KB를 활용하지 못한다. 반대로 B200용 tile은 sm_120에서 overflow가 난다.
  - Cluster multicast가 GeForce에는 없어(1x1x1) multicast TMA 기반 설계는 sm_120에서 검증할 수 없다.
  - `sm_120a`/`sm_100a` arch-specific cubin은 서로 호환되지 않는다.
  - 결론적으로 **5090에서 검증할 수 있는 것은 수치 포맷(scale factor layout, quantize/dequantize epilogue), TMA 로딩, 알고리즘 정확도까지이고, sm_100용 mainloop는 별도 작업이다.** 상세는 01-architecture.md 참조.
- **SW**: CUDA 12.8+ (가능하면 12.9/13.x의 `compute_120f`), CUTLASS 4.x (`examples/79_blackwell_geforce_gemm`), CuTe DSL, Triton (sm_120 지원 버전), Nsight Compute.
- **주제 예시**: NVFP4 GEMM 및 grouped GEMM(MoE) 최적화, FP4 attention (FlashInfer SM120a MXFP8 prefill RFC #3628 참조), wave quantization 분석 (170 SM 기준).
- **난이도**: ★★★★

### 6.3 로컬 LLM 서빙 시스템 연구
- **왜 이 GPU인가**: 단일 카드 TTFT가 1초 미만(RAG-8k 450 ms)이고, multi-LoRA를 c64까지 확장할 수 있다 (arXiv 2601.09527). 한편 32 GB 한계 때문에 27B급에서 context 길이, MTP, 런타임 선택의 trade-off가 뚜렷하게 드러난다 (Tom's Hardware 2026). 스케줄러, KV cache 관리, speculative decoding 연구에 쓰기 좋은 제약 환경이다.
- **SW**: vLLM, SGLang, llama.cpp, TensorRT-LLM, AIPerf, DCGM-Exporter.
- **난이도**: ★★

### 6.4 LoRA / QLoRA fine-tuning
- **왜 이 GPU인가**: BF16 dense 209.5 TFLOPS와 32 GB로 7–14B는 LoRA, 더 큰 모델은 QLoRA로 다룰 수 있다 (정확한 한계는 미확인이며 모델, 시퀀스 길이, 옵티마이저에 따라 실측 필요). NVFP4 학습/QAT 실험의 입문 플랫폼으로도 쓸 수 있다.
- **SW**: PyTorch ≥ 2.7 (cu128), Unsloth, PEFT/TRL, bitsandbytes, TensorRT Model Optimizer (QAT).
- **주의**: FP32 accumulate가 반속인 GeForce 특성 때문에 학습 처리량 상한은 PRO/데이터센터 대비 낮다.
- **난이도**: ★★

### 6.5 PCIe-only 멀티 GPU (P2P 없음) 병렬화 연구
- **왜 이 GPU인가**: P2P, NVLink, MIG가 모두 없어 통신이 host 메모리를 거친다. arXiv 결과처럼 TP=2가 오히려 느려지는 영역이 존재한다. pipeline parallel, expert parallel, 통신 압축, 비동기 offload 같은 **통신을 회피하는 설계**의 효과를 측정할 수 있는 현실적인 테스트베드다.
- **SW**: NCCL (최신), vLLM/SGLang TP·PP, DeepSpeed/FSDP, `nvidia-smi topo -m`, PCIe Gen5 x16 대역폭 측정.
- **주의**: 커뮤니티 P2P 패치 드라이버는 비공식이고 지원 여부도 불명확하다 (2025-03 시점 50 시리즈 미지원). 연구 결과를 이에 의존하게 만드는 것은 권장하지 않는다.
- **난이도**: ★★★

### 6.6 전력, 에너지 효율 (power limiting) 연구
- **왜 이 GPU인가**: TGP 575 W로 대역폭 병목(decode) 구간과 연산 병목(prefill) 구간의 전력 대비 성능 곡선이 크게 다를 가능성이 있다. 16-pin 커넥터 이슈를 고려하면 power cap을 걸고 운용할 동기도 있다. arXiv 2601.09527처럼 Wh/MTok을 지표로 삼을 수 있다.
- **SW**: `nvidia-smi -pl` (power limit), NVML/DCGM, clock locking (`nvidia-smi -lgc`), vLLM + AIPerf.
- **난이도**: ★
- **질문 예시**: power limit을 400–450 W로 낮췄을 때 decode 처리량 손실은 어느 정도인가 (미확인이며 실측 대상).

### 6.7 그래픽 + AI 결합 (neural rendering)
- **왜 이 GPU인가**: 데이터센터 Blackwell(B200)에는 없는 RT core 4세대, neural shaders, DLSS 4 MFG, Mega Geometry, AMP가 있다. Neural Texture Compression, Neural Materials, Neural Radiance Cache 같은 "셰이더 내 소형 MLP" 연구는 GeForce/RTX PRO 계열에서만 할 수 있다.
- **SW**: RTX Kit (Neural Shaders, NTC, RTXNS), DirectX 12 Agility SDK (Cooperative Vectors, 미확인), Vulkan 1.4, OptiX, Slang.
- **난이도**: ★★★

### 6.8 비디오 인코딩 + AI 파이프라인
- **왜 이 GPU인가**: NVENC 3개와 NVDEC 2개가 있고, 4:2:2 H.264/HEVC 인코드·디코드와 AV1 UHQ를 지원한다. 디코드 → AI 추론(검출, 초해상도, 캡셔닝) → 재인코드를 한 카드 안에서 처리하는 파이프라인의 처리량과 지연을 연구할 수 있다.
- **SW**: Video Codec SDK, FFmpeg (NVENC/NVDEC), DeepStream, TensorRT, NVIDIA Maxine/Broadcast SDK.
- **난이도**: ★★
