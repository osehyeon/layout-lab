# 03. NVIDIA RTX PRO 6000 Blackwell (Workstation / Max-Q / Server Edition)

> 작성일: 2026-09-11. 1차 자료 사본은 [`sources/rtx-pro-6000/`](sources/rtx-pro-6000/SOURCES.md)에 있음.
> 표기 규칙: 처리량은 NVIDIA 공식 수치를 **환산 없이** 적고 값마다 **[sparse]**(2:4 structured sparsity 적용, dense의 2배) 또는 **[dense]** 를 붙임. 데이터시트·제품 페이지 공식 표기가 있으면 그 값, 없으면 백서 표의 dense 값. 모든 peak 수치는 GPU Boost Clock 기준 이론값임. **(계산값)** = 공식 수치를 클럭 비율 등으로 환산한 값, **(미확인)** = 1차 자료로 확인하지 못한 값.
> 아키텍처 공통 사항(SM 구조, 5세대 Tensor Core, sm_100과 sm_120의 차이 등)은 [01-architecture.md](01-architecture.md)를 참조.

## 1. 개요

RTX PRO 6000 Blackwell은 **GB202** 다이(GeForce RTX 5090과 같은 다이)를 쓰는 NVIDIA의 최상위 전문가용(professional) GPU이다. 에디션은 세 가지이며, 칩 구성(188 SM, 96 GB GDDR7)은 같고 **전력·클럭·냉각·소프트웨어 지원 범위**가 다르다.

#### Server Edition (최대 600 W 설정 가능, boost 2,430 MHz)

NVIDIA는 Server Edition의 정밀도별 전체 표를 공개하지 않았다. 공식 수치는 반올림된 값이고, **sparse와 dense 표기가 섞여 있다**.

| 정밀도 | NVIDIA 공식 표기 | 비고 |
|---|---|---|
| **FP4** | **4 PFLOPS [sparse]** [PP-SE], [DS-SE-NV] | 반올림 값 |
| **FP8** | **2 PFLOPS [sparse]** [PP-SE], [LN-SE] | |
| **FP16 / BF16** | **1 PFLOP [sparse]** [PP-SE], [LN-SE] | |
| **TF32** | **234 TFLOPS [dense]** [PP-SE], [LN-SE] | 이 항목만 dense 표기 |
| **FP32** | 120 TFLOPS [dense] [PP-SE], [DS-SE-NV] | 2,430 MHz로 계산하면 117. 공식 120과 약 3% 차이 (미확인) |
| RT | 355 TFLOPS | |
| **FP64** | 미공개 | ≈1.8~1.9 TFLOPS [dense] (1/64, 계산값) |

- sparse/dense 판별 근거: Workstation 값에 clock 비율(2,430 / 2,617 = 0.9285)을 곱하면 FP4 ≈3,742 [sparse], FP8 ≈1,871 [sparse], FP16 ≈936 [sparse], TF32 ≈234 [dense], RT ≈354.5가 나온다.
  - 공식 4 / 2 / 1 PF는 sparse 값을 반올림한 것과 맞는다.
  - 234 TFLOPS는 dense 값과 맞는다.
  - 두 에디션의 SM 수와 clock당 처리량이 같다고 가정한 계산이다.
- Server Edition을 450 W 이하로 power-cap하면 지속 클럭과 성능이 떨어진다. 전력 설정별 수치는 공개되지 않음 (미확인).

#### 참고: clock·SM당 tensor 처리량 (계산값)

- PRO(Workstation): FP16(FP32 acc) dense 503.8 TF ÷ (188 SM × 2.617 GHz) = **1,024 FLOP/clk/SM**. FP8 = 2,048, FP4 = 4,096, TF32 = 512.
- GeForce RTX 5090: FP16(FP32 acc) 209.5 TF ÷ (170 × 2.407 GHz) = **512 FLOP/clk/SM**. PRO의 절반이다 (§4.1 참조).

## 3. 지원 기능

### 3.1 MIG (Multi-Instance GPU): "Universal MIG"

- **최대 4개 인스턴스**를 지원한다. 확인한 자료: [WP] Table 3, [DS-WS], [DS-MQ], [DS-SE-NV], [NEWS].
  - Workstation / Max-Q: **1x 96 GB, 2x 48 GB, 4x 24 GB** [WP] Table 3, [DS-WS].
  - Server: "Up to 4 MIGs @ 24GB" [DS-SE-NV].
- **Universal MIG**: 인스턴스마다 전용 메모리·캐시·SM·엔진을 가지며, **그래픽과 AI 워크로드를 동시에** 실행할 수 있다 [DS-SE-NV]. NVIDIA는 이 제품을 "the first NVIDIA MIG-enabled GPUs designed to accelerate both graphics and compute workloads"라고 소개했다 [BLOG-VGPU19].
- 인스턴스별 SM 수와 MIG profile 이름(예: `1g.24gb`)은 1차 자료로 확인하지 못함 (미확인).
- **Workstation / Max-Q에서 MIG 쓰는 조건** [MIG-GUIDE]:
  - 드라이버 **R575(≥ 575.51.03)** 이상, CUDA 12.
  - 최소 vBIOS: Workstation 98.02.55.00.00, Max-Q 98.02.6A.00.00.
  - 기본 display mode가 graphics이므로 **DisplayModeSelector(≥ 1.72.0)로 compute 모드 전환**이 필요하다 (`--gpumode=compute`). 이러면 해당 GPU의 **물리 디스플레이 출력이 꺼진다**. 단일 GPU 워크스테이션이라면 SSH 접속을 먼저 준비해야 한다.
  - 포럼에는 MIG 활성화 실패 사례가 보고되어 있다 [FORUM-MIG].
- Server Edition은 기본값이 "Display Off" 모드(BAR1 128 GiB)다 [PB-SE].

- vGPU 19.0에서 MIG와 vGPU(time-slicing)를 결합하면 **GPU 1장당 최대 48 VM**을 동시에 돌릴 수 있다 [BLOG-VGPU19].

### 3.3 ECC, NVLink, 보안

- **ECC**: 세 에디션 모두 "96 GB GDDR7 with ECC" [DS-*]. Server는 기본값 Enabled [PB-SE].
- **NVLink**: **없음**. Max-Q와 Server에는 "Not supported"가 명시되어 있고 [LN-MQ], [PB-SE], [LN-SE], Workstation 데이터시트에는 NVLink 항목 자체가 없다 [DS-WS]. 멀티 GPU 통신은 전부 PCIe Gen5(이론상 x16 한 방향 약 63 GB/s, 계산값) 또는 네트워크를 거친다.
- **Confidential Computing**:
  - **Server Edition: 지원** [DS-SE-NV]. NVIDIA는 "first universal GPU to enable secure AI with NVIDIA Confidential Computing"이라고 발표했다 [BLOG-SE].
  - NVIDIA CC Deployment Guide v7.1(2026년 4월)의 Blackwell 지원 조합: **RTX PRO 6000 Single GPU**, CPU는 AMD SEV-SNP 또는 Intel TDX, Host OS Ubuntu 25.10, Guest Ubuntu 24.04 LTS [CC-GUIDE]. **multi-GPU CC는 B200만 등재**되어 있어 RTX PRO 6000은 단일 GPU CC만 가능하다.
  - Workstation / Max-Q: 데이터시트에 CC 항목 없음 (미확인, 포럼에 문의만 있음 [FORUM-CC]).
- **Secure boot with root of trust**: Server 지원 [DS-SE-NV], [PB-SE].

### 3.4 Compute capability sm_120: sm_100(B200)과의 차이 (요약)

자세한 내용은 [01-architecture.md](01-architecture.md) 참조.

- **CC 12.0**(RTX PRO 6000, RTX 5090 공통). B200/GB200은 CC 10.0 [CUDA-GPUS].
- sm_120에는 **`tcgen05.mma`와 Tensor Memory(TMEM)가 없다**. 그래서 sm_100의 2-SM UMMA, TMEM 기반 GEMM 파이프라인도 쓸 수 없다.
- 대신 SM8x처럼 **warp-level 동기식 `mma.sync`**(register operand)를 쓴다. TMA는 지원된다 [COLFAX].
- 결과: sm_100용 CUTLASS/cuDNN/FlashAttention 커널은 그대로 돌지 않고 SM12x 전용 경로가 필요하다. 반대로 SM8x용 GEMM 커널은 SM12x에서 대체로 괜찮게 돈다 [COLFAX].

### 3.5 NVFP4 on sm_120: block-scaled `mma.sync`

- NVFP4 block-scaling을 지원하는 PTX 명령은 사실상 하나다 [COLFAX]:
  `mma.sync.aligned.kind::mxf4nvf4.block_scale.scale_vec::4X.m16n8k64.row.col.f32.e2m1.e2m1.f32.ue4m3`
  - E2M1 operand, UE4M3 scale factor, K=64당 scale 4개(= 16원소당 scale 1개), FP32 accumulate.
- MXFP8/MXFP6/MXFP4(`kind::mxf8f6f4`)도 block-scaled `mma.sync`로 쓸 수 있다 [FORUM-PTX].
- 컴파일 주의: arch-specific target이 필요하다. `-arch=sm_120a`만 주면 ptxas가 sm_120으로 컴파일해서 block-scale 명령이 거부될 수 있다. `-gencode arch=compute_120a,code=sm_120a`를 명시할 것 [FORUM-PTX].
- Colfax 튜토리얼 커널은 RTX PRO 6000에서 이론 FP4 peak(약 2,000 TFLOPS dense)의 **약 60%**를 달성했고, FP16 dense GEMM 대비 **약 3배** 빨랐다 [COLFAX].

### 3.6 그래픽 / 뉴럴 렌더링 / 전문가용 기능

- **Neural shaders / Cooperative Vectors**: Microsoft와 함께 만든 Cooperative Vectors API(DX12, Vulkan)로 픽셀·레이트레이싱 등 **모든 셰이더에서 Tensor Core에 접근**할 수 있다. Slang의 differentiable shading과 결합해 neural texture compression(block-compressed 포맷 대비 최대 7:1 VRAM 절감), RTX Neural Materials, Neural Radiance Cache, RTX Neural Faces 등을 구현한다 [WP] pp.39–40.
- **SER 2.0**, **RTX Mega Geometry**(최대 100배 많은 ray-traced triangle), 4세대 RT core의 ray-triangle intersection 2배 [DS-WS], [WP].
- **DLSS 4 Multi Frame Generation** [DS-WS], [DS-MQ], [DS-SE-NV].
- **9세대 NVENC**(AV1/HEVC 품질 약 5% 개선, 4:2:2), **6세대 NVDEC**(H.264 디코드 2배, 4:2:2). RTX 6000 Ada는 3개/3개였고 이 제품은 4개/4개다 [WP] pp.28–30.
- 전문가용 기능:
  - enterprise driver, ISV 인증, IT 관리 도구 [DS-WS]
  - AI Management Processor [DS-WS]
  - Server Edition의 RTX PRO Sync3D Stereo 헤더 [PB-SE]
  - 2026년 6월 개정 데이터시트는 로컬 에이전트용 NVIDIA NemoClaw 지원을 언급한다 [DS-WS]

**핵심: GeForce는 FP32 accumulate 처리량이 절반이다.** NVIDIA 공식 GeForce 백서 Table 3를 보면 RTX 5090은 다음과 같다 [GF-WP]:

- FP16 / BF16 / FP8의 FP32-accumulate 수치가 FP16-accumulate의 정확히 절반이다 (FP16: 419 → 209.5, FP8: 838 → 419).
- TF32(104.8)도 SM·clock당 PRO의 절반이다.

반면 PRO 백서 Table 4에서 RTX PRO 6000은 FP16-acc와 FP32-acc가 같은 값이다 [WP]. clock·SM당으로 보면 FP16(FP32 acc)은 PRO 1,024 vs 5090 512 FLOP/clk/SM이다 (계산값). FP4 FP32-acc(4,096)와 INT8은 절반으로 제한되지 않는다.

그래서 BF16 학습이나 FP32 누산 추론처럼 대부분의 실제 딥러닝 GEMM에서, 같은 다이인데도 PRO 6000이 5090보다 **이론상 약 2.4배**(503.8 vs 209.5) 높다. 이 제한이 의도적인 제품 차별화라는 해석은 서드파티 주장이다 [TOLD].

## 7. 요약

- **같은 칩**(GB202, 188 SM, 96 GB GDDR7 ECC, 512-bit)을 쓰는 세 에디션:
  - **Workstation**: 600 W, 1,792 GB/s, boost 2,617 MHz
  - **Max-Q**: 300 W, 1,792 GB/s, 2,280 MHz
  - **Server**: 최대 600 W 설정 가능, passive, **1,597 GB/s**, 2,430 MHz, vGPU/CC 지원
- FP4는 데이터시트 기준 **4000 AI TOPS [sparse]**(WS)다.
- RTX 5090 대비 결정적 차이는 **FP32-accumulate FP16/BF16/FP8과 TF32의 full rate**(5090은 절반), 3배 메모리, ECC, MIG, pro 드라이버다.
- 약점:
  - NVLink 없음 → 멀티 GPU는 PCIe/네트워크에 의존
  - FP64 1/64
  - sm_120의 tcgen05/TMEM 부재 → B200용 커널 생태계를 그대로 쓸 수 없음
